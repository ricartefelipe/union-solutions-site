# Matriz de requisitos do portal

Requisito → tela → API → regra e autorização → persistência → falhas e estados → testes. Atualizada em 01/11/2026. Caminhos: `F` = `frontend/src/app/(portal)`, `R` = `backend/.../infrastructure/rest`, `A` = `backend/.../application`, `T` = `backend/src/test/java/.../portal`, `E` = `e2e/tests`. Os resultados estão em [`EVIDENCIAS.md`](EVIDENCIAS.md).

Transversal, válido para todas as linhas: contrato de erro único (`R/WebSupport.java`: validação com detalhes por campo, `409` de versão ou regra, `500` com código de correlação); formulários e botões mostram a mensagem da API com foco no alerta e confirmação em diálogo (`components/forms.tsx`); carregamento, erro, registro inexistente e sem acesso (`F/loading.tsx`, `F/error.tsx`, `F/not-found.tsx`, `app/sem-acesso`); listas limitadas a 100 por página na API e paginadas ou com aviso de corte na tela; isolamento por organização e projeto (`A/AccessPolicy.java`, `T/IsolationTest.java`).

## Fora do escopo, por decisão

Cobrança, checkout, assinatura eletrônica, CRM, chat e integrações com os produtos não existem e não são prometidos pela interface. Prazo de atendimento só aparece quando registrado em contrato.
